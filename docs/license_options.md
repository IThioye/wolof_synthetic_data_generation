# Source-code licence options

This project still needs an explicit licence before public release. A licence
for the project code does not replace the separate licences and attribution
requirements of datasets, papers, templates, Eflomal, or Lexique.

## Common choices

| Licence | What others may do | Main obligation | Suitable when |
| --- | --- | --- | --- |
| MIT | Use, modify, redistribute, and include the code in proprietary products | Keep the copyright and licence notice | Maximum simplicity and adoption are preferred |
| Apache-2.0 | Similar permissive reuse, including proprietary products | Keep notices; contributors grant an explicit patent licence | A permissive licence with clearer patent protection is preferred |
| BSD-3-Clause | Permissive reuse, including proprietary products | Keep notices and do not use the author's name for endorsement | A short academic-friendly permissive licence is preferred |
| GPL-3.0 | Use, modify, and redistribute | Distributed derivative programs must remain GPL-3.0 and provide source | Improvements to distributed derivatives should remain open |
| AGPL-3.0 | GPL-style copyleft, also covering network-hosted modified versions | Offer corresponding source to users interacting with the service | Hosted derivatives should also remain open |

## Practical recommendation

For this research repository, MIT is the simplest default. Apache-2.0 is a good
alternative if the explicit patent grant matters. GPL-3.0 or AGPL-3.0 should be
chosen only if reciprocal open-sourcing is an intentional requirement, because
they place stronger conditions on downstream integrations.

Creative Commons licences are appropriate for the report, slides, or a dataset,
but are generally not recommended as the main software licence. Dataset release
terms should be decided separately from the source-code licence.
